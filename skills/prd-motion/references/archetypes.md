# 모션 유형 카탈로그

기능의 **핵심 동사**와 **바뀌는 양의 모양**으로 유형을 고른다. 각 유형에는 언제 쓰는지, 무엇이 움직이는지, 무엇을 조작하게 하는지, 구현 요점이 있다. 코드는 그대로 붙여 쓰는 용도가 아니라 뼈대다. 대상과 수치는 그 PRD의 것으로 바꾼다.

## 목차
1. 썰물 Drain: 쌓인 것이 빠진다
2. 합류 Converge: 흩어진 것이 하나로 모인다
3. 임계 감지 Threshold: 신호가 선을 넘으면 울린다
4. 경로 Route: 길이 그려지고 따라간다
5. 재배치 Rebalance: 자원이 수요 쪽으로 옮겨간다
6. 슬롯 분배 Slot: 한 줄이 시간 칸으로 나뉜다
7. 분류 Sort: 섞인 것이 칸으로 나뉜다
8. 매칭 Match: 양쪽이 짝을 짓는다
9. 변환 Transform: 원재료가 구조화된 결과물이 된다
10. 순환 Loop: 단계가 돌며 상태가 진행된다
11. 확산 Spread: 한 곳에서 여러 곳으로 퍼진다
12. 비교 Before/After: 숫자가 바뀐다 (KPI 전용)
13. 분기 Branch: 규칙에 따라 갈래로 나뉜다
14. 레이스 Race: 같은 일을 두 방식이 경주한다
15. 재정렬 Reorder: 줄 선 순서가 바뀐다
16. 간트 압축 Compress: 하루 타임라인에서 빈 시간이 빠진다 (히어로용)

## 고르기 표

| 기능 설명에 이런 말이 있으면 | 바뀌는 양 | 1순위 | 2순위 |
|---|---|---|---|
| 대기 제거, 자동화, 처리 시간 단축, 적체 해소 | 남은 건수, 대기 시간 | 썰물 | 슬롯 분배 |
| 통합, 연동, 수집, 동기화, 파이프라인, 단일 뷰 | 연결된 소스 수, 사용 가능한 기능 | 합류 | 확산 |
| 예측, 모니터링, 이상 탐지, 경보, 알림 | 지표와 임계치의 관계 | 임계 감지 | 분류 |
| 안내, 내비게이션, 온보딩, 개인화 동선, 가이드 | 진행 단계, 남은 시간 | 경로 | 순환 |
| 배치, 할당, 최적화 권고, 재고 이동, 예산 배분 | 자원 위치와 수, 부하 균형 | 재배치 | 매칭 |
| 예약, 스케줄링, 시간 배정, 순번 | 슬롯별 잔여, 줄 길이 | 슬롯 분배 | 썰물 |
| 분류, 필터, 세그먼트, 트리아지, 우선순위 | 칸별 개수 | 분류 | 임계 감지 |
| 매칭, 추천, 배정, 연결 | 짝지어진 수, 적합도 | 매칭 | 분류 |
| 생성, 요약, OCR, 추출, 변환, AI 작성 | 원재료 → 구조화 결과 | 변환 | 분류 |
| 승인, 결재, 워크플로, 학습 루프, 피드백 | 단계 진행, 회차 | 순환 | 경로 |
| 확산, 공유, 배포, 롤아웃, 알림 발송 | 도달 범위 | 확산 | 합류 |
| 자동 승인, 규칙 엔진, 기준 금액, 조건부 처리 | 경로별 건수 | 분기 | 분류 |
| 순서 최적화, 경로 최적화, 배정 순서 | 같은 작업의 총 소요 | 레이스 | 경로 |
| 우선순위 재정렬, 대기열 정렬, 동적 순번 | 순번, 유휴 시간 | 재정렬 | 분류 |
| 체류·리드타임·처리 기간 단축 (대표 가치) | 하루 중 빈 시간 | 간트 압축 | 썰물 |

**고르기 팁**: 분류(Sort)는 "어느 칸에 들어가나"가 핵심이고, 분기(Branch)는 "어느 길로 처리되나"가 핵심이다. 칸에 쌓인 개수가 중요하면 분류를, 경로마다 걸리는 시간이나 사람 손이 중요하면 분기를 쓴다. 매칭은 좌우 이분 그래프만이 아니다. 배차처럼 지도 위에서 짝을 짓는 경우에는 지도 위에 경로를 그리는 매칭으로 만든다.

## 1. 썰물 Drain

**언제**: 기능이 기다림이나 적체를 없앨 때. 히어로 장면으로 가장 많이 쓴다.
**움직이는 것**: 줄(점들)이 앞에서부터 빠져나가고, 남은 점들이 앞으로 당겨진다. 혼잡을 나타내는 붉은 영역이 줄어든다. After 상태에서는 멈추지 않고 흐르는 점이 지나간다.
**조작**: 스크롤 스크럽, 재생 버튼, 진행 슬라이더. 옆 보드에 남은 인원과 대기 시간이 같이 줄어든다.

핵심 수식은 진행값 p에 대한 순수 함수다. 거꾸로 스크롤하면 그대로 되감긴다.

```js
// q = {n, x0, y0, rowLen, sp, rowH}  줄 하나. 점 k는 앞에서 k번째.
var START=.04, END=.72, TRAVEL=.2;
function slot(q,k){var row=Math.floor(k/q.rowLen),c=k-row*q.rowLen,col=row%2===0?c:q.rowLen-1-c;return [q.x0-col*q.sp,q.y0+row*q.rowH]} // 지그재그 줄
function slotF(q,f){var a=Math.floor(f),t=f-a,p=slot(q,a),n=slot(q,a+1);return [lerp(p[0],n[0],t),lerp(p[1],n[1],t)]}
// 매 프레임
q.R = clamp((p-START)/(END-START),0,1)*q.n;      // 빠져나간 사람 수(소수)
for(k=0;k<q.n;k++){
  if(k>=q.R){ pos=slotF(q,k-q.R) }                 // 줄에 남은 사람: 앞으로 당겨진다
  else{ r=START+(END-START)*k/q.n; t=(p-r)/TRAVEL; pos=along(path[k],ease(clamp(t,0,1))); alpha=t>1?1-(t-1)*4:1 } // 빠져나간 사람: 경로를 따라 이동 후 사라짐
}
remaining=Math.ceil(q.n-q.R); wait=Math.ceil(baseWait*remaining/q.n);
```

경로(`path[k]`)는 줄 머리 → 처리 지점 → 다음 단계 → 목적지 꼭짓점 배열이고, 누적 길이로 위치를 구한다. 혼잡 영역은 `createRadialGradient`의 투명도를 `remaining/n`에 비례시킨다. 점 개수는 PRD 수치와 1:1로 맞추면 설득력이 크다. 줄 하나에 300개 이하가 적당하다.

## 2. 합류 Converge

**언제**: 데이터 통합, 시스템 연동, 여러 채널을 한 화면으로 모을 때. 보통 의존 체인의 첫 기능이다.
**움직이는 것**: 왼쪽 소스 노드에서 색이 다른 입자가 베지어 곡선을 타고 가운데 허브로 모이고, 허브에서 오른쪽 기능 노드로 흘러간다. 연결이 끊긴 소스는 흐린 노드에 붉은 파동이 퍼진다(고립 상태).
**조작**: 소스를 켜고 끄는 토글. 기능 노드마다 필요한 입력과 상태(동작 / 부분 동작 / 대기)를 PRD의 "활용 데이터" 표에 따라 계산한다.
**첫 등장**: 처음 보일 때 소스가 하나씩 연결되는 모션. 사용자가 먼저 만지면 멈춘다.

```js
function status(o){ // o.need = 필요한 소스 키 배열, o.dep = 선행 기능
  var have=o.need.filter(function(k){return on[k]}).length, r=have/o.need.length;
  if(o.dep && status(byKey(o.dep)).r===0) return {r:0,blocked:true};
  return {r:r};
}
// 입자: 소스→허브(ph0) 도착 시, 그 소스를 필요로 하면서 켜진 기능 중 하나로 보낸다(ph1). 없으면 허브에서 사라진다.
function curve(a,b){return mode==='h'
  ?[a,[a[0]+(b[0]-a[0])*.6,a[1]],[a[0]+(b[0]-a[0])*.4,b[1]],b]
  :[a,[a[0],a[1]+(b[1]-a[1])*.6],[b[0],a[1]+(b[1]-a[1])*.4],b]}
```

좁은 화면(캔버스 폭 620px 미만)에서는 세로 레이아웃(`mode='v'`)으로 바꾼다. 소스는 위, 허브는 가운데, 기능은 아래에 두고 논리 크기를 600×820으로 바꾼다. 라벨이 읽히는 크기로 유지하기 위해서다.

## 3. 임계 감지 Threshold

**언제**: 예측, 모니터링, 이상 탐지, 경보.
**움직이는 것**: 대상(구역, 장비, 고객군)마다 카드를 두고, 실시간처럼 흔들리는 스파크라인과 게이지를 보여 준다. 임계선을 넘으면 카드 테두리가 깜빡이고 경보 목록에 항목이 밀려 들어온다.
**조작**: 임계치 슬라이더. 바꾸면 경보가 생기거나 사라진다. 경보 문구는 PRD 예시 문장 형식을 따른다.

- 스파크라인 흔들림은 표시용이다. 경보 판정은 흔들림이 없는 값으로 한다. 그래야 경계값에서 경보가 깜빡거리지 않는다.
- 경보에는 "다음 행동"을 붙인다. 이 행동은 다른 기능(재배치 등)의 입력이 된다.
- 게이지 위에 임계치 위치를 세로선으로 표시해서, 슬라이더와 기준선이 함께 움직이게 한다.

## 4. 경로 Route

**언제**: 개인화 안내, 내비게이션, 온보딩, 단계별 가이드.
**움직이는 것**: 휴대폰 목업 안의 작은 SVG 지도에 경로가 `stroke-dashoffset`으로 그려지고, 점이 `getPointAtLength`로 따라간다. 단계 목록이 같은 진행값에 맞춰 차례로 켜진다(완료 / 현재 / 대기). 남은 시간이 줄어든다.
**조작**: 사용자 유형 탭(예: 일반 / 환승, 신규 / 기존). 탭마다 경로와 단계가 다르다. "다시 보기" 버튼.

```js
var L=line.getTotalLength(); line.style.strokeDasharray=L;
(function f(now){ var u=clamp((now-t0)/DUR,0,1);
  line.style.strokeDashoffset=L*(1-u); var pt=line.getPointAtLength(L*u); dot.setAttribute('cx',pt.x); dot.setAttribute('cy',pt.y);
  steps.forEach(function(s,i){ li[i].className = u>=s.f ? (i===current(u)?'cur':'done') : '' }); // s.f = 경로상 위치(0~1), 단계별 소요시간 누적 비율로 정한다
  if(u<1) requestAnimationFrame(f); })(performance.now());
```

키오스크, 출력물, 알림 같은 보조 채널이 PRD에 있으면, 같은 경로 데이터로 영수증이 한 줄씩 출력되는 모션을 덧붙인다.

## 5. 재배치 Rebalance

**언제**: 인력 배치, 재고 이동, 예산 배분, 서버 증설 같은 최적화 권고.
**움직이는 것**: 대상마다 자원 아이콘(창구, 차량, 서버)이 한 줄로 늘어서 있다. 켜진 아이콘은 강조색, 새로 추가된 아이콘은 정상 색이다. 권고를 적용하면 아이콘이 시차를 두고 하나씩 켜진다(`transition-delay: calc(var(--d)*60ms)`).
**조작**: 대상별 −/+ 스테퍼와 "권고 적용", "처음 상태로" 버튼.
**계산**: 부하 = 수요 ÷ 자원 수 같은 단순한 식을 쓰고 "단순 추정"이라고 표시한다. 권고 수는 임계 감지 기능의 임계치를 기준으로 계산해서 두 기능이 같은 숫자를 말하게 한다.

```js
function waitOf(z){return z.baseWait*z.baseLanes/z.lanes}
function needLanes(z){return clamp(Math.ceil(z.baseWait*z.baseLanes/S.th),1,MAX)}
```

## 6. 슬롯 분배 Slot

**언제**: 예약, 스케줄링, 시간 배정, 순번 발급.
**움직이는 것**: 한 줄로 선 점 24개 정도가 시간 칸(열)으로 흩어진다. 각 점은 `transform` 전환에 `transition-delay: calc(var(--i)*25ms)`를 줘서 물결처럼 이동한다. Before일 때 점 색은 주의, After일 때는 정상이다.
**조작**: Before/After 토글, 슬롯 선택과 예약. 예약하면 잔여 수가 줄고, 처리하는 쪽 화면(직원 화면, 관리자 목록)에 그 사람이 시간순으로 끼워 들어가며 강조된다.

점 위치는 컨테이너 크기에서 퍼센트로 계산하고, `resize` 때 다시 놓는다.

## 7. 분류 Sort

**언제**: 세그먼트, 필터, 트리아지, 우선순위화, 스팸이나 이상 거래 분류.
**움직이는 것**: 섞여 있는 점이나 카드가 위에서 떨어지며 기준선을 지나 칸으로 나뉜다. 칸마다 개수가 올라간다. 기준을 바꾸면 점이 칸 사이를 옮겨 간다.
**조작**: 분류 기준 슬라이더나 체크박스(예: 위험 점수 기준, 세그먼트 조건).

```js
// item = {score, x, y, tx, ty}; 기준이 바뀌면 bin과 목표 위치만 다시 계산하고 매 프레임 위치를 목표로 보간
items.forEach(function(it){ it.bin = it.score>=S.cut ? 'high' : it.score>=S.cut*.6 ? 'mid' : 'low'; });
layoutBins(); // 칸 안에서 격자로 tx,ty 배정
it.x += (it.tx-it.x)*.12; it.y += (it.ty-it.y)*.12;
```

점마다 PRD의 실제 속성(고객 유형, 금액대)을 색이나 모양으로 넣으면 분류가 의미를 가진다.

## 8. 매칭 Match

**언제**: 추천, 배정, 수요와 공급 연결, 멘토링이나 배차.
**움직이는 것**: 왼쪽에 수요, 오른쪽에 공급 노드가 있고, 매칭되면 둘 사이에 곡선이 그려지며 양쪽 노드가 같은 색으로 바뀐다. 매칭되지 않은 노드는 흐리게 남는다.
**조작**: 매칭 조건(거리, 적합도 기준)을 바꾸면 선이 끊어지거나 새로 이어진다. 매칭률이 숫자로 바뀐다.

선은 SVG `path`로 그리고 `stroke-dashoffset` 전환으로 나타나게 한다. 매칭 계산은 탐욕 알고리즘(점수가 가장 높은 쌍부터)이면 충분하다.

## 9. 변환 Transform

**언제**: 생성형 AI, 요약, OCR, 데이터 추출, 문서 자동 작성.
**움직이는 것**: 왼쪽의 원재료(흐트러진 문서, 영수증, 대화 로그)에서 조각이 떨어져 나와 오른쪽 구조화된 카드의 칸으로 날아가 채워진다. 칸이 채워질 때마다 체크 표시가 켜진다.
**조작**: 입력 예시 바꾸기(샘플 2~3개 탭). 결과 카드가 다른 값으로 다시 채워진다.

조각은 `getBoundingClientRect`로 출발점과 도착점을 구하고, 복제한 요소를 `transform`으로 날린다(FLIP). 결과 값은 미리 준비한 예시이며, 실제 AI 호출을 흉내 냈다면 그렇다고 밝힌다.

## 10. 순환 Loop

**언제**: 승인과 결재 흐름, 학습 루프, 반복 개선, 상태 머신.
**움직이는 것**: 원형이나 사각 궤도에 단계 노드가 있고, 토큰이 단계를 돌며 이동한다. 반려되면 이전 단계로 되돌아가는 화살표가 붉게 켜진다. 회차가 늘어날수록 지표가 좋아지는 루프라면 중앙 숫자가 올라간다.
**조작**: 단계별 승인/반려 버튼, 또는 "한 바퀴 더" 버튼.

## 11. 확산 Spread

**언제**: 배포, 롤아웃, 알림 발송, 네트워크 효과, 로드맵 확장.
**움직이는 것**: 한 노드에서 동심원 파동이 퍼지며 주변 노드가 차례로 켜진다(거리순 지연). 단계(Pilot → Roll-out)마다 켜지는 범위가 넓어진다.
**조작**: 단계 선택 탭. 범위와 도달 수가 바뀐다.

## 12. 비교 Before/After (KPI 전용)

기능 장면으로는 쓰지 않는다. KPI 섹션에서만 쓴다.

- 행마다 지표 이름, Before, 측정 방법, 막대, After 목표를 둔다.
- 막대는 처음 보일 때 한 번 차오른다.
- 숫자는 `countTo`로 올라간다.
- PRD가 "예시" 또는 "추후 확정"이라고 적은 값은 그대로 표시한다.

## 13. 분기 Branch

**언제**: 자동 승인/반려, 규칙 엔진, 조건부 라우팅. 예: 유형과 금액 기준으로 자동 승인, 팀장 승인, 반려로 나뉜다.
**움직이는 것**: 위에서 내려오는 점이 마름모 판단 지점에서 여러 갈래로 갈라져 흐른다. 사람 손이 필요한 갈래 끝에는 결재함이나 상담 콘솔이 있고, 그 앞에 점이 쌓인다.
**조작**: 기준값(금액, 점수) 슬라이더와 Before/After 방식 토글. 기준을 바꾸면 갈래별 비율과 쌓이는 양이 바뀐다.
**읽는 값**: 갈래별 건수, 사람 결재 감소율.

## 14. 레이스 Race

**언제**: 순서 최적화, 경로 최적화처럼 같은 일을 다른 방식으로 하는 기능.
**움직이는 것**: 같은 시간축에 Before 줄과 After 줄을 위아래로 둔다. 현재 시각 선이 왼쪽에서 오른쪽으로 지나가며 두 줄이 동시에 그려진다. 대기는 빗금, 처리는 색 막대, 이동은 점선이다. 먼저 끝난 줄 끝에 도착 시각 태그가 붙고, 마지막에 "n분 먼저"가 나온다.
**조작**: 작업 구성(검사 항목 등)과 시작 시각. 바꾸면 최적 순서를 다시 계산하고 레이스를 처음부터 다시 그린다.
**계산**: 항목이 4개 이하이면 순열 전체를 비교하는 완전 탐색으로 충분하다. 대기 시간은 "시각에 따라 변하는 예측 곡선"으로 둬야 순서가 결과를 바꾼다. 대기가 고정이면 순서와 상관없이 합이 같다.

```js
function waitAfter(k,t){var r=R[k];return Math.max(r.min, r.w0 + r.g*t)} // g>0 붐비는 중, g<0 풀리는 중
function run(order){var t=start,segs=[];order.forEach(function(k,i){var w=waitAfter(k,t);segs.push({k:k,t0:t,w:w,s:R[k].s});t+=w+R[k].s;if(i<order.length-1)t+=WALK});return {segs:segs,end:t}}
best = perms(list).map(run).sort(byEnd)[0];
```

w0와 g는 기본 입력에서 PRD 데모 수치가 그대로 나오도록 맞춘다.

## 15. 재정렬 Reorder

**언제**: 동적 대기열, 우선순위 정렬, 준비된 순서대로 처리하는 기능.
**움직이는 것**: 실제 업무 화면을 닮은 카드 목록(진료실 화면, 작업 큐)에서 카드가 FLIP으로 미끄러지며 자리를 바꾼다. 상태(처리 중 / 준비됨 / 대기 / 완료)는 테두리와 흐림으로 구분한다.
**조작**: 정렬 방식 토글(Before 예약순 / After 준비순), 시각 슬라이더와 재생, 카드별 수동 우선(응급 등) 버튼.
**계산**: 처리자(의사, 작업자)를 하나 두는 이산 시뮬레이션이다. 매 시점 규칙에 따라 다음 건을 고르고, 준비된 건이 없으면 유휴 시간을 더한다. 두 방식의 종료 시각과 유휴 시간을 나란히 보여 준다. `MK.flip(els, reorderFn)`을 쓴다.

## 16. 간트 압축 Compress (히어로용)

**언제**: 대표 가치가 "체류 시간, 리드타임, 처리 기간 단축"일 때.
**움직이는 것**: 대상 여러 건(환자, 주문, 민원)이 한 줄씩 하루 시간축 위에 놓인다. 각 줄은 대기 구간(빗금)과 처리 구간(단계별 색)으로 이뤄진다. 진행값 p에 따라 대기 구간만 줄어들어 줄이 왼쪽으로 당겨지고, 줄 끝 태그의 총 소요 시간이 바뀐다.
**맞추기**: 예시 줄들의 평균 총 소요가 PRD Before 값(예: 152분)과 정확히 같게 대기 구간을 정규화한다. After 배율은 PRD 목표(예: −35%)로 계산한다. 처리 시간은 줄이지 않는다. 처리 시간이 그대로인데 기다림만 사라진다는 것이 메시지이기 때문이다.
